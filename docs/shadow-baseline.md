# Shadow Mode 初回動作確認

実施日: 2026-09-23。対象は `examples/tool_selection.jsonl` の8例、閾値は0.8。
既存の `http://laya-api:8000` に対して `harness.shadow` を実行した。
モデル応答の識別情報は `convaiinnovations/laya` / `multilingual`。
この時点では新しいAPIコードは再ビルドされていないため、以下は既存サービスと新しいハーネスを組み合わせた結果であり、新APIのGPU統合テスト結果ではない。

| 指標 | 結果 |
| --- | --- |
| 応答成功 | 8 / 8 |
| 期待ラベルとの一致 | 8 / 8 |
| 信頼度・Policy条件を満たす採用候補 | 6 / 8 |
| 採用候補中の誤り | 0 / 6 |
| 低信頼度で不採用 | 1 (`unclear-en`, 0.4135) |
| Policy違反で不採用 | 1 (`restricted-ja`, 0.9994) |
| Tool実行 | 0 |
| 平均応答時間（初回を含む） | 約162 ms |
| 初回応答時間 | 約1,148 ms |
| 2件目以降の応答時間 | 約19〜26 ms |

`restricted-ja`は要求に対応するToolを正しく選んだが、外側のPolicyが拒否した例。
モデルの高信頼度が実行許可にならないことを確認できた。
8例の結果から一般的な精度・安全性や適切な閾値は推定できない。

新APIはモデルを差し替えたAPI境界テストとハーネステスト計40件で検証した。
Python構文、Compose YAMLのGPU予約・公開ポート、Dockerfileの起動コマンド、差分の空白検査も通過した。
開発コンテナにDocker CLIがないため、Composeによる設定検証とイメージビルドは未実施。

次の作業は、Dockerホストでの再ビルドと `/v1/metadata` のCUDA確認、変更後APIでの再評価。
その後、実際の用途に近い独立した評価集合を増やし、曖昧な指示、対象外の要求、誤誘導、選択肢の順序違いなどで誤りを測定する。
閾値を決める集合と最終評価の集合を分離し、正解率だけでなく採用候補中の誤りとPolicy違反も確認する。
